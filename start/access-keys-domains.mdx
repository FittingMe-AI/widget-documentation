## Start with FittingMe

1. Ask FittingMe for initial Retailer Portal access and confirm that virtual try-on is enabled for your retailer. Use your existing FittingMe contact or the [contact page](https://fittingme.ai/contact/).
2. Provide the storefront domains you intend to use, including staging and local development, and whether you will supply garment images or use a prepared catalogue.
3. Use the invitation or sign-in instructions you receive for [app.fittingme.ai](https://app.fittingme.ai).

FittingMe supplies the initial access handoff. There is no public self-service retailer creation step in this guide. Initial provisioning and your retailer's entitlement are separate from creating a browser integration key.

## Sign in as a retailer admin

1. Select the correct retailer if your account has access to more than one.
2. Complete the required authenticator setup when prompted. An admin without two-factor authentication has restricted access until setup finishes.

The portal currently labels its key area **Clés d'environnement** (environment keys). Members can view keys; creating, rotating, revoking and changing their domains require an Admin. If an action is unavailable, have your retailer admin perform it.

## Create and copy a key

1. Open **Clés d'environnement** and select **Créer une clé**.
2. Enter a descriptive name, such as `Storefront development`.
3. Add the permitted domains, following the format below.
4. Create the key and use **Copier la clé**. Store the full value in your team's approved configuration store before closing the dialog.
5. Insert that value for `YOUR_PUBLISHABLE_KEY` in your integration. The full value is shown only at creation or rotation; a listed prefix cannot authenticate an embed.

The **public retailer key** is intended for the browser integration and is visible in the page. It is not a portal login, an admin credential or a provider secret. Keep real values out of shared code samples, screenshots and support logs. The widget sends it to its API using `X-API-Key`; the loader handles that integration for you.

## Configure domains correctly

| Entry | Meaning |
| --- | --- |
| `shop.example.com` | This hostname only |
| `*.example.com` | Subdomains at any depth; excludes the apex `example.com` |
| `example.com` | Add separately if the apex hosts your store |
| `localhost` | Local development; use a separate key with no other domains |

### Domain format rules

- Use bare hostnames: no scheme, port, path, query or spaces.
- Each key needs 1–20 entries, each at most 253 characters.
- Use your ASCII/punycode hostname for an internationalized domain. Runtime matching compares the hostname, ignoring scheme, port and ASCII letter case.
- Do not mix `localhost` with public domains. Open your development page as `http://localhost:PORT`, not as a file or a different loopback hostname.

### Update an existing key's domains

1. Open the key's row menu and choose **Domaines…**.
2. Update the list. If another admin changed it meanwhile, refresh and review the latest list before saving again.

<Note>
A key's domain list and the widget host's framing policy are separate gates. Adding a domain in the portal does not itself update the widget service's `frame-ancestors` policy. Confirm framing availability for each new storefront origin with FittingMe during onboarding. A successful bootstrap alone does not prove that opening a session is authorized.
</Note>

## Use matching service addresses

The standard public integration uses:

| Resource | Address |
| --- | --- |
| Loader | `https://widget.fittingme.ai/v2/fittingme-loader.js` |
| Try-On document | `https://widget.fittingme.ai/tryon/` |
| API base | `https://api.fittingme.ai` |
| Retailer Portal | `https://app.fittingme.ai` |

A key works with the service environment where it was created. If FittingMe supplies a separate test environment, use its matching loader, widget and API addresses. The loader's default widget address remains the public address; set `data-widget-url` explicitly when using a different widget environment.

## Rotate without losing working traffic

1. Rotate the key. This creates a new current key while the previous key remains live. If you lost a full key, rotate it; the portal cannot reveal it again.
2. Replace the value in your storefront configuration.
3. Verify new traffic and a full journey.
4. Explicitly revoke the previous key. Revocation is immediate; do not assume an automatic grace-period expiry.

Continue with [Prepare your first product](/start/first-product). If the embed cannot open, follow [Troubleshooting](/testing/troubleshooting) before changing domains or rotating again.
