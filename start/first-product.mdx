---
title: "Prepare your first product"
description: "Choose a stable product identifier and a garment image that the service can fetch."
---

Before copying a quickstart, have an enabled retailer, a full public retailer key and an authorized storefront origin. Complete [Access, keys and domains](/start/access-keys-domains) first.

## Choose the product context

Use a stable identifier from your own product system, for example `YOUR_PRODUCT_ID`. It identifies the garment/color context the shopper sees. Use the same identity consistently in your integration, catalogue handoff and retailer-owned analytics. Do not use a shopper identifier or generate a new product identifier on each page view.

With a supplied image, a product need not already exist in the prepared catalogue. Retailer entitlement and explicit product exclusions still apply. With catalogue integration, the identifier must match the one prepared by FittingMe exactly.

## Supply a garment image

- Use a direct image URL on a publicly reachable HTTPS host.
- Choose an image that clearly shows the garment and selected color, without a collage or unrelated product.
- Make sure the URL returns usable image bytes to FittingMe's services without a shopper login or browser-only cookie. A product-page URL that returns HTML is not an image URL.

The exact URL constraints are in [Configuration parameters](/reference/configuration#garment-image-url). In particular, whitespace, embedded credentials and fragments are rejected. Private network and local image addresses are not usable. Use a stable URL that stays accessible for the journey; a short-lived signed URL can expire between bootstrap and generation.

### Verify image access

1. Open the URL in a private browser window and verify the image.
2. Confirm that your CDN allows a service-side fetch. Browser success alone cannot establish that: anti-bot rules, redirects and network restrictions can still prevent generation.

Bootstrap validates the URL structurally without downloading the garment, so an eligible boot outcome is not an image-download test.

## First product with a supplied image

1. Select one garment and color from your store.
2. Record its stable product identifier and direct HTTPS image URL.
3. Copy the [provided-button quickstart](/quickstarts/provided-button), or [custom-button quickstart](/quickstarts/custom-button).
4. Replace `YOUR_PUBLISHABLE_KEY`, `YOUR_PRODUCT_ID` and `https://images.example.com/YOUR_GARMENT.jpg`. These are placeholders, not working credentials or assets.
5. Serve the file from an authorized origin. Expect an eligible boot outcome, then an available Try-On button.
6. Open the drawer and complete the actual journey. Verify that the generated garment corresponds to the selected image. Close and reopen, then check focus and completion as described in the quickstart.

Use [direct fittingme/3](/quickstarts/direct-protocol) only if you need to implement the host protocol yourself.

## First product from a catalogue

1. Send FittingMe the product identifiers and garment imagery for preparation.
2. Wait for confirmation of the prepared product identifiers and Try-On availability.
3. Use the loader **without** `data-garment-image-url`.

Follow the separate [prepared-catalogue walkthrough](/guides/prepared-catalogue), including its handoff checklist and example.

## Keep the selected garment correct

The product and supplied image are fixed when an embed is created. Changing a script attribute or the visible product gallery does not update its session. When the shopper selects another product, color or image, close and replace the embed using [Product and image changes](/guides/product-changes). Omitting an image chooses catalogue behavior; an explicitly invalid or unavailable supplied image never silently falls back to catalogue imagery.
