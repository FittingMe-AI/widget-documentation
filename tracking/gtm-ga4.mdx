## Before you start

Have these prerequisites ready:

- An existing web GTM container and a configured Google tag for your GA4 web stream.
- Access to its Preview tools and DebugView.
- The [vendor-neutral adapter](/tracking/usage).

Use the container and consent configuration already owned by your store.

## Push one data-layer event per record

Use this sink with `subscribeTryOn`. Keep one subscription in your storefront lifecycle; do not recreate it from a repeatedly firing GTM tag.

```javascript
window.dataLayer = window.dataLayer || [];
function sendTryOnToDataLayer(record) {
  window.dataLayer.push({
    event: record.name,
    fm_product_id: record.product_id,
    fm_placement: record.placement,
    fm_boot_outcome: record.boot_outcome,
    fm_transport_code: record.transport_code,
    fm_open_origin: record.open_origin
  });
}
// Pass send: sendTryOnToDataLayer to subscribeTryOn, with your existing
// consent-state function as canTrack. Save its unsubscribe function.
```

Use `.push()` without replacing an existing data layer. Keep the event and its values in the same push. This follows Google's [data-layer guidance](https://developers.google.com/tag-platform/tag-manager/datalayer).

## Configure GTM

1. Under **Variables**, create Data Layer Variables for `fm_product_id`, `fm_placement`, `fm_boot_outcome`, `fm_transport_code` and `fm_open_origin` (version 2).
2. Under **Triggers**, create a **Custom Event** trigger. Use `^tryon_(boot|open|close|complete)$` as its event name and enable regular-expression matching. This limits it to these four example events. See Google's [custom-event trigger instructions](https://support.google.com/tagmanager/answer/7679219?hl=en).
3. Under **Tags**, create a **Google Analytics: GA4 Event** tag. Select the intended GA4 stream/Measurement ID, use the built-in **Event** variable for the event name, and attach the trigger above. Your Google tag must already be configured for that destination. See Google's [GA4 event setup](https://support.google.com/tagmanager/answer/13034206?hl=en).
4. Map event parameters as follows. Omit values that are null if your tag configuration supports conditional parameters; do not replace them with an earlier event's values.

| GA4 parameter | GTM Data Layer Variable |
| --- | --- |
| `product_id` | `fm_product_id` |
| `placement` | `fm_placement` |
| `boot_outcome` | `fm_boot_outcome` |
| `transport_code` | `fm_transport_code` |
| `open_origin` | `fm_open_origin` |

### Optional reporting dimensions

If you need these custom parameters in reporting, create the appropriate event-scoped custom dimensions in GA4. Choose dimensions deliberately; unique per-event identifiers are poor reporting dimensions. Google's [custom-dimensions guide](https://support.google.com/analytics/answer/14240153?hl=en) explains their scope. Do not rename a Try-On event to `purchase` or `add_to_cart`.

## Preserve consent handling

Keep your CMP's existing consent defaults, updates and tag consent settings. Use your store's actual consent state for the adapter's `canTrack`; the local test's unconditional gate is not a production consent policy. The shopper's consent inside Try-On is not your site's analytics consent.

Do not add a Custom HTML tag that grants consent or initializes a second Google tag. Follow Google's [consent-mode setup](https://developers.google.com/tag-platform/security/guides/consent), using the CMP's GTM template/Consent APIs where applicable. Test both denied and granted states; this recipe does not decide which consent mode your store should use.

## Verify three separate boundaries

| Boundary | Browser action | Expected evidence |
| --- | --- | --- |
| Retailer emission | Open and close a real embed; inspect the new `dataLayer` entries | One `tryon_open` and one `tryon_close`, with the correct product and placement. Complete a journey and close it to observe `tryon_complete`. |
| GTM processing | Start **Preview**, connect Tag Assistant to that product page and inspect the custom events | Intended GA4 tag fires once per eligible event; Variables show the matching payload and consent state. |
| GA4 ingestion | Use the intended property's **DebugView** with debugging enabled | The same event names arrive with the expected parameters. A fired tag or HTTP request alone does not prove this. |

Google documents [DebugView and its debugging prerequisites](https://support.google.com/analytics/answer/7201382?hl=en). A denied consent state or filtering can affect what appears. Do not infer failure or success from the data-layer array alone.

### Repeat before publishing

1. Repeat the boundary checks after SPA navigation and a product change.
2. Close and reopen an already completed result. Do not expect a second completion unless a new completion occurred.
3. Check that another subscription is not duplicating the events.
4. Submit/publish the GTM change through your store's normal review process only after the checks pass.
