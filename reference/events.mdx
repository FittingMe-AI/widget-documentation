Subscribe with `window.FittingMe.on(handler)`. Server-side facts are [Delivered Events](/reference/delivered-events), not Page Events.

## Event catalogue

| `type` | Additional fields | Meaning | Replayed to a new subscriber? |
| --- | --- | --- | --- |
| `bootstrap` | `outcome`; optional `transport_code` | Latest bootstrap outcome. | Yes, for each embed with a known outcome. |
| `opened` | `origin`: `tap` or `command` | The drawer opened. | No. |
| `closed` | None | The drawer closed. | No. |
| `completed` | None | The drawer closed on a completed result. | No. |
| `tryon_result_revealed` | `try_on_reference` | First display of a try-on render. `/v4` and `/v5` loaders only. | No. |

Every event has `type` and `embed`, the container element. No event has a timestamp, product, session or order identifier. Switch on `type` and ignore unknown types.

## Bootstrap outcome

| `outcome` | Meaning |
| --- | --- |
| `eligible` | The embed can offer its journey. |
| `ineligible` | The embed has no journey for this product. |
| `indeterminate` | Bootstrap could not decide. The product is not ineligible. |

On `indeterminate`, `transport_code` is `network`, `timeout` or an HTTP status string. Use it for diagnosis only.

## Opening origin

`origin` is `tap` for the widget's entry point and `command` when your page calls the loader. A custom button that calls `open(container)` gives `command`.

## Timing and ownership

Subscribe before the shopper can interact, and filter on `embed`. A late subscription receives only the bootstrap state.

## Completion is not conversion

The widget sends `completed` when the drawer closes on a completed result, after `closed`. A displayed result alone sends nothing. A reload can send it again for the same result. If you remove the embed or unsubscribe on `closed`, you can lose `completed`.

## Shown try-on renders

The widget sends `tryon_result_revealed` at the first display of a render only. A render opened from saved try-ons sends nothing. A render that finishes while the drawer is closed counts when the drawer opens again. A re-run is a new try-on with a new reference.

`try_on_reference` is 32 lowercase hexadecimal characters. It matches the `try_on_reference` column of Delivered Events. Production datasets do not have that column yet. FittingMe tells you when it reaches your dataset. If Web Crypto refuses to compute the reference, the widget writes one console line and sends no event.

### Indicative, not an invoice

This event is indicative, never an invoice. A page misses events when consent is refused, when it subscribes late or when the shopper leaves.
