You read these server-side Try-On facts in BigQuery. They are not [Page Events](/reference/events).

## Get access

FittingMe provisions one dataset per company, `delivered_events_YOUR_KEY`, with one read-only view, `events_v1`.

1. Send FittingMe the Google group and service accounts that read the view.
2. Get the full view path from FittingMe. Access covers this dataset only.
3. Query from your own Google Cloud project, which pays. Keep copied tables in `europe-west1`.

## Columns

In production, `events_v1` has the first eight columns below, in this order. The ninth, `try_on_reference`, is not in production datasets yet. FittingMe tells you when it reaches your dataset.

| Column | Type | Meaning |
| --- | --- | --- |
| `event_type` | STRING | One of the [event types](#event-types). |
| `occurred_at` | TIMESTAMP | Server time of the fact, in UTC. |
| `journey` | STRING | Always `tryon`. |
| `product_id` | STRING | Your product identifier. |
| `session_key` | STRING | 32 lowercase hexadecimal characters per session. |
| `correlation_id` | STRING | Your [correlation identifier](#join-your-own-analytics), else `FM_` and the `session_key`. |
| `event_id` | STRING | Unique UUID. |
| `retailer_id` | STRING | Lowercase Retailer UUID. |
| `try_on_reference` | STRING | 32 lowercase hexadecimal characters on `tryon_result_revealed` rows, else `NULL`. Reveal rows of 2026-09-11 and earlier stay `NULL`. |

When `try_on_reference` reaches your dataset, it has the value of the [`tryon_result_revealed` Page Event](/reference/events#shown-try-on-renders).

A session is one shopper's Try-On journey on one product. It lasts up to 48 hours. A return to the same product in the same browser within that time resumes the session, with the same `session_key`.

## Event types

| `event_type` | What happened | How often |
| --- | --- | --- |
| `session_created` | The shopper opened the Try-On journey. | Once per session. Resuming a session does not repeat it. |
| `tryon_photo_ingested` | FittingMe accepted a shopper photo. | Once per new photo. |
| `tryon_launch` | FittingMe accepted a try-on request. | Once per request or re-run. |
| `tryon_result_revealed` | First display of a try-on render. | Once per try-on. |
| `cart_intent_expressed` | The shopper tapped **Back to product** on the result. | Once per tap, before `journey_exited`. |
| `journey_exited` | The shopper closed the drawer or left the page with it open. | At most once per opening. |
| `tryon_photo_refused` | A shopper photo was refused. | Once per refusal. |

These facts are observations, not conversions:

- `cart_intent_expressed` is not an add-to-cart: it has no size or variant.
- `journey_exited` is not an abandonment: the shopper can reopen and continue.
- `tryon_photo_refused` has no reason, origin or photo.

Once `try_on_reference` reaches your dataset, count its distinct values for shown renders. Rows are observations, not an invoice.

## Reading rules

- **Freshness.** No delay is guaranteed. Read overlapping windows and deduplicate on `event_id`.
- **Stable contract.** Nothing is renamed or removed, and new columns come last.
- **Test traffic.** Ask FittingMe for a separate test Retailer.
- **Retention.** Facts stay for 13 months.
- **Erasure.** An erased correlation identifier becomes the `FM_` stand-in. Rows that you copied into your own tables are yours to erase.

## Join your own analytics

Supply a correlation identifier, such as a visit number, with `data-correlation-id` or [`window.FittingMe.setCorrelationId(id)`](/reference/javascript#correlation-identifier). Never use a personal identifier, such as an email address.

## Example queries

Replace `FITTINGME_PROJECT.delivered_events_YOUR_KEY` with your path.

Daily funnel in Paris time:

```sql
SELECT
  DATE(occurred_at, 'Europe/Paris') AS day,
  COUNT(DISTINCT IF(event_type = 'session_created', session_key, NULL)) AS sessions,
  COUNT(DISTINCT IF(event_type = 'tryon_photo_ingested', session_key, NULL)) AS with_photo,
  COUNT(DISTINCT IF(event_type = 'tryon_launch', session_key, NULL)) AS with_launch,
  COUNT(DISTINCT IF(event_type = 'tryon_result_revealed', session_key, NULL)) AS with_render,
  COUNT(DISTINCT IF(event_type = 'cart_intent_expressed', session_key, NULL)) AS with_cart_intent
FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1`
WHERE occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
GROUP BY day
ORDER BY day
```

A session that starts one day and continues the next counts on both days.

Incremental copy without duplicates:

```sql
MERGE `YOUR_PROJECT.YOUR_DATASET.fittingme_events` AS target
USING (
  SELECT *
  FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1`
  WHERE occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 2 DAY)
) AS source
ON target.event_id = source.event_id
WHEN NOT MATCHED THEN
  INSERT ROW
```

When FittingMe announces a new column, add it to your table before the next run.

Renders shown and cart intents per visit:

```sql
SELECT
  visits.visit_id,
  COUNTIF(events.event_type = 'tryon_result_revealed') AS renders_shown,
  COUNTIF(events.event_type = 'cart_intent_expressed') AS cart_intents
FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1` AS events
JOIN `YOUR_PROJECT.YOUR_DATASET.visits` AS visits
  ON visits.visit_id = events.correlation_id
WHERE NOT STARTS_WITH(events.correlation_id, 'FM_')
  AND events.occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)
GROUP BY visits.visit_id
```
