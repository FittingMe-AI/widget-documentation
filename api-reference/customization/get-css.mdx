This endpoint retrieves the CSS stylesheet currently applied to a specific widget key. Use it to inspect existing styles, back up your customizations before making changes, or sync your local stylesheet with what Fitting Me is actively serving.

## Endpoint

```
GET https://api.fitting.me/v1/widget-keys/:id/css
```

## Headers

<ParamField header="Authorization" type="string" required>
  Your API key, provided as a Bearer token. Example: `Bearer YOUR_API_KEY`
</ParamField>

## Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the widget key whose CSS you want to retrieve. Widget key IDs begin with the `wk_` prefix.
</ParamField>

## Example Request

```bash
curl https://api.fitting.me/v1/widget-keys/wk_01HXYZ123/css \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Response

### 200 OK

Returns the raw CSS string with a `Content-Type: text/css` header. The response body contains exactly the stylesheet stored against the widget key — no wrapping JSON object.

### 204 No Content

Returned when the widget key exists but no custom CSS has been applied to it yet. The response body is empty.

## Example Response

```css
.fitting-widget {
  font-family: 'Inter', sans-serif;
  color: #1a1a1a;
  background-color: #ffffff;
  border-radius: 8px;
  padding: 16px;
}
```

<Note>
  If no CSS has been applied to the widget key yet, the API returns `204 No Content` with an empty body rather than an empty string. Make sure your integration handles this status code explicitly so you don't treat a missing stylesheet as an error.
</Note>
