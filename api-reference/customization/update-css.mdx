This endpoint replaces the entire CSS stylesheet for a widget key with the CSS string you provide in the request body. As soon as the request succeeds, Fitting Me begins serving the new styles — there is no separate publish or deploy step required. Send an empty body to clear all custom CSS and revert the widget to its applied theme defaults.

## Endpoint

```
PUT https://api.fitting.me/v1/widget-keys/:id/css
```

## Headers

<ParamField header="Authorization" type="string" required>
  Your API key, provided as a Bearer token. Example: `Bearer YOUR_API_KEY`
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `text/css`. The API expects a raw CSS string in the request body, not a JSON payload.
</ParamField>

## Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the widget key you want to update. Widget key IDs begin with the `wk_` prefix.
</ParamField>

## Request Body

Send your CSS rules as a raw string in the request body. The body must be valid CSS; do not wrap it in JSON or any other format.

## Example Request

```bash
curl -X PUT https://api.fitting.me/v1/widget-keys/wk_01HXYZ123/css \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: text/css" \
  --data-binary '.fitting-widget {
  font-family: Inter, sans-serif;
  color: #1a1a1a;
  background-color: #ffffff;
  border-radius: 8px;
  padding: 16px;
}

.fitting-widget__button {
  background-color: #ef7025;
  color: white;
  border: none;
  padding: 8px 16px;
  border-radius: 4px;
  cursor: pointer;
}'
```

## Response

### 200 OK

The CSS was validated and stored successfully. The response body contains the CSS string that is now being served for this widget key, confirming exactly what was saved.

### 400 Bad Request

Returned when the request body contains invalid CSS that the API cannot parse. Correct the syntax and retry.

### 404 Not Found

Returned when no widget key exists for the provided `id`. Double-check the identifier and confirm the key has been created in your Fitting Me account.

## Removing Custom CSS

To clear all custom styles and revert the widget to its applied theme, send a `PUT` request with an empty string as the body. The widget will immediately fall back to the default theme styles.

<Warning>
  This endpoint performs a full replacement. Every `PUT` request overwrites the entire stylesheet stored for the widget key — it does not merge or append. If you send only a subset of your CSS rules, any styles not included in the new body will be lost. To safely add or update specific rules, first call `GET /widget-keys/:id/css` to retrieve the current stylesheet, merge your changes locally, then `PUT` the complete result.
</Warning>

<Tip>
  Before pushing styles through the API, prototype and validate them in your browser's DevTools. Inspect the widget element, paste your CSS into the Styles panel, and confirm the visual result looks correct. This tight feedback loop is much faster than iterating via API calls and avoids accidentally serving broken styles to end users.
</Tip>
