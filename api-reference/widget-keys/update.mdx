description: "PATCH /widget-keys/:id — update a Fitting Me widget key's name, description, theme, or active status. All fields are optional."
---

Use this endpoint to update one or more properties of an existing widget key. You can rename a key, change its theme, update its description, or toggle it between active and inactive — all in a single request. You only need to supply the fields you want to change.

## Endpoint

```
PATCH https://api.fitting.me/v1/widget-keys/:id
```

## Headers

<ParamField header="Authorization" type="string" required>
  Your Fitting Me API key, supplied as `Bearer YOUR_API_KEY`.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the widget key you want to update.
</ParamField>

## Request Body

<ParamField body="name" type="string">
  A new display name for the widget key.
</ParamField>

<ParamField body="description" type="string">
  An updated human-readable description for this widget key. Pass an empty string (`""`) to clear an existing description.
</ParamField>

<ParamField body="theme" type="string">
  The visual theme to apply to the widget. Accepted values are `default`, `minimal`, `branded`, and `dark`.
</ParamField>

<ParamField body="active" type="boolean">
  Set to `false` to deactivate the widget key, which prevents the widget from rendering on any page using this key's embed token. Set to `true` to reactivate it.
</ParamField>

## Example Request

```bash
curl --request PATCH \
  --url https://api.fitting.me/v1/widget-keys/wk_01HXYZ1234ABCDEF567890 \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Homepage Widget (Redesign)"
  }'
```

## Response

A successful request returns a `200 OK` status and the full updated widget key object.

<ResponseField name="id" type="string">
  The unique identifier for this widget key.
</ResponseField>

<ResponseField name="key" type="string">
  The embed token used to initialize the Fitting Me widget on your site.
</ResponseField>

<ResponseField name="name" type="string">
  The display name for this widget key, reflecting any update you applied.
</ResponseField>

<ResponseField name="description" type="string">
  The description for this widget key, or `null` if none is set.
</ResponseField>

<ResponseField name="theme" type="string">
  The visual theme applied to this widget key.
</ResponseField>

<ResponseField name="active" type="boolean">
  The current active status of this widget key.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp indicating when this widget key was originally created.
</ResponseField>

<ResponseField name="updatedAt" type="string">
  ISO 8601 timestamp reflecting the time of this update.
</ResponseField>

## Example Response

```json
{
  "id": "wk_01HXYZ1234ABCDEF567890",
  "key": "fme_live_aBcDeFgHiJkLmNoPqRsTuVwXyZ1234567890",
  "name": "Homepage Widget (Redesign)",
  "description": "Embedded on the main product pages",
  "theme": "branded",
  "active": true,
  "createdAt": "2024-05-14T10:23:45Z",
  "updatedAt": "2024-05-21T14:05:37Z"
}
```

<Note>
  This endpoint uses partial update semantics — only the fields you include in the request body are modified. Any fields you omit remain exactly as they were. To unset a nullable field such as `description`, explicitly pass an empty string.
</Note>
