Use this endpoint to create a new widget key for your Fitting Me account. Each widget key includes a unique embed token that you use to initialize the widget on your site. Once created, you can customize the widget's appearance through its associated CSS configuration.

## Endpoint

```
POST https://api.fitting.me/v1/widget-keys
```

## Headers

<ParamField header="Authorization" type="string" required>
  Your Fitting Me API key, supplied as `Bearer YOUR_API_KEY`.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Request Body

<ParamField body="name" type="string" required>
  A display name for the widget key. Use something descriptive that helps you identify where this key is used, such as `"Storefront Widget"` or `"Checkout Page"`.
</ParamField>

<ParamField body="description" type="string">
  A human-readable description providing additional context about this widget key's purpose or placement.
</ParamField>

<ParamField body="theme" type="string">
  The visual theme to apply to the widget. Accepted values are `default`, `minimal`, `branded`, and `dark`. Defaults to `default` if not provided.
</ParamField>

## Example Request

```bash
curl --request POST \
  --url https://api.fitting.me/v1/widget-keys \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Storefront Widget",
    "description": "Embedded on the main product pages",
    "theme": "branded"
  }'
```

## Response

A successful request returns a `201 Created` status and the newly created widget key object.

<ResponseField name="id" type="string">
  The unique identifier for this widget key.
</ResponseField>

<ResponseField name="key" type="string">
  The embed token used to initialize the Fitting Me widget on your site. Treat this value like a secret — do not expose it in public repositories.
</ResponseField>

<ResponseField name="name" type="string">
  The display name you provided for this widget key.
</ResponseField>

<ResponseField name="description" type="string">
  The description you provided, or `null` if none was supplied.
</ResponseField>

<ResponseField name="theme" type="string">
  The theme applied to this widget key. Reflects the value you supplied, or `"default"` if none was specified.
</ResponseField>

<ResponseField name="active" type="boolean">
  Whether this widget key is currently active. Newly created keys are `true` by default.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp indicating when this widget key was created.
</ResponseField>

<ResponseField name="updatedAt" type="string">
  ISO 8601 timestamp indicating when this widget key was last modified.
</ResponseField>

```json
  "active": true,
  "createdAt": "2024-05-14T10:23:45Z",
  "updatedAt": "2024-05-14T10:23:45Z"

```

## Error Responses

| Status | Description |
|--------|-------------|
| `400 Bad Request` | The request body is malformed or missing required fields. Check that `name` is present and that `theme` is one of the accepted values. |
| `401 Unauthorized` | The `Authorization` header is missing or your API key is invalid. |
| `422 Unprocessable Entity` | The request was well-formed but failed validation — for example, `name` was an empty string. |

<Tip>
  Store the returned `key` value securely after creation. While you can always retrieve the full widget key object by ID, the embed token is sensitive and should be kept out of version control.
</Tip>
