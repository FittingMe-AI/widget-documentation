Widget keys are the core building blocks of every Fitting Me integration. Each key is a unique identifier that ties a specific widget instance to your site, allowing you to embed, configure, and style it independently from any other widget you create.

## What is a widget key?

A widget key is a unique token that you use to embed a Fitting Me widget on your site. When you create a key, Fitting Me generates a secure, embeddable token — the `key` value — that you reference in your embed script. This token tells Fitting Me which widget configuration and CSS styles to load, so every page that uses the same key gets the same widget experience.

Keys can be scoped to a specific site, page, or use case. For example, you might create one key for your checkout flow and a separate key for your support sidebar — each with its own appearance and settings. This scoping keeps your configurations isolated and easy to manage.

## Widget key properties

Every widget key object returned by the Fitting Me API contains the following fields:

<ResponseField name="id" type="string">
  The unique identifier for this widget key, generated by Fitting Me. Use this value when making API calls to retrieve, update, delete, or style the key.
</ResponseField>

<ResponseField name="key" type="string">
  The embeddable token you place in your embed script. This value is set at creation and never changes, even if you rename the key.
</ResponseField>

<ResponseField name="name" type="string">
  A human-readable label you assign to the widget key. This name appears in your Fitting Me dashboard and helps you identify the key at a glance.
</ResponseField>

<ResponseField name="description" type="string">
  An optional description for the widget key. Use this field to record additional context, such as which page or team owns the widget.
</ResponseField>

<ResponseField name="active" type="boolean">
  Indicates whether the widget key is currently active. When set to `false`, widgets using this key will stop rendering on all embeds immediately.
</ResponseField>

<ResponseField name="createdAt" type="string (ISO 8601)">
  The timestamp at which this widget key was created.
</ResponseField>

<ResponseField name="updatedAt" type="string (ISO 8601)">
  The timestamp at which this widget key was last updated.
</ResponseField>

## API endpoints

The Fitting Me API exposes the following endpoints for managing widget keys and their CSS styles. All requests must include a valid `Authorization: Bearer YOUR_API_KEY` header.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/widget-keys` | Create a new widget key. |
| `GET` | `/widget-keys` | List all widget keys for your account. |
| `GET` | `/widget-keys/:id` | Retrieve a single widget key by ID. |
| `PATCH` | `/widget-keys/:id` | Update a key's name, description, or active status. |
| `DELETE` | `/widget-keys/:id` | Permanently delete a widget key. |
| `GET` | `/widget-keys/:id/css` | Retrieve the CSS styles associated with a widget key. |
| `PUT` | `/widget-keys/:id/css` | Replace the CSS styles associated with a widget key. |

## Common use cases

Widget keys are flexible enough to support a wide range of embedding scenarios. Some of the most common include:

- **E-commerce checkout widget** — Embed a size-recommendation or product-fitting widget directly on your checkout or product detail pages.
- **Support chat widget** — Power a help or live-chat experience with its own isolated configuration and branding.
- **Onboarding flow widget** — Guide new users through a setup or configuration flow with a dedicated widget scoped to your onboarding pages.
