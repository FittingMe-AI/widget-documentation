Vous lisez ces faits Try-On côté serveur dans BigQuery. Ce ne sont pas des [événements de page](/fr/reference/events).

## Obtenir l’accès

FittingMe met à disposition un dataset par entreprise, `delivered_events_YOUR_KEY`, avec une vue en lecture seule, `events_v1`.

1. Envoyez à FittingMe le groupe Google et les comptes de service qui lisent la vue.
2. Obtenez auprès de FittingMe le chemin complet de la vue. L’accès couvre ce seul dataset.
3. Exécutez vos requêtes depuis votre propre projet Google Cloud, qui les paie. Gardez les tables copiées dans `europe-west1`.

## Colonnes

`events_v1` comporte neuf colonnes, dans cet ordre. Les datasets de production n’ont pas encore la colonne `try_on_reference`. FittingMe vous prévient lorsqu’elle arrive dans votre dataset.

| Colonne | Type | Signification |
| --- | --- | --- |
| `event_type` | STRING | L’un des [types d’événements](#types-d’événements). |
| `occurred_at` | TIMESTAMP | Heure serveur du fait, en UTC. |
| `journey` | STRING | Toujours `tryon`. |
| `product_id` | STRING | Votre identifiant produit. |
| `session_key` | STRING | 32 caractères hexadécimaux minuscules par session. |
| `correlation_id` | STRING | Votre [identifiant de corrélation](#joindre-vos-propres-analyses), sinon `FM_` suivi de la `session_key`. |
| `event_id` | STRING | UUID unique. |
| `retailer_id` | STRING | UUID de l’enseigne, en minuscules. |
| `try_on_reference` | STRING | 32 caractères hexadécimaux minuscules sur les lignes `tryon_result_revealed`, sinon `NULL`. |

Lorsque `try_on_reference` arrive dans votre dataset, elle porte la valeur de l’[événement de page `tryon_result_revealed`](/fr/reference/events#rendus-d’essayage-affichés).

## Types d’événements

| `event_type` | Ce qui s’est passé | Fréquence |
| --- | --- | --- |
| `session_created` | L’acheteur a ouvert le parcours Try-On. | Une fois par session. |
| `tryon_photo_ingested` | FittingMe a accepté une photo de l’acheteur. | Une fois par nouvelle photo. |
| `tryon_launch` | FittingMe a accepté une demande d’essayage. | Une fois par demande ou relance. |
| `tryon_result_revealed` | Premier affichage d’un rendu d’essayage. | Une fois par essayage. |
| `cart_intent_expressed` | L’acheteur a appuyé sur **Retour au produit** dans le résultat. | Une fois par appui, avant `journey_exited`. |
| `journey_exited` | L’acheteur a fermé le panneau ou a quitté la page panneau ouvert. | Au plus une fois par ouverture. |
| `tryon_photo_refused` | Une photo de l’acheteur a été refusée. | Une fois par refus. |

Ces faits sont des observations, pas des conversions :

- `cart_intent_expressed` n’est pas un ajout au panier : il ne porte ni taille ni variante.
- `journey_exited` n’est pas un abandon : l’acheteur peut rouvrir et continuer.
- `tryon_photo_refused` ne porte ni cause, ni origine, ni photo.

Lorsque `try_on_reference` arrive dans votre dataset, comptez ses valeurs distinctes pour les rendus affichés.

## Règles de lecture

- **Fraîcheur.** Aucun délai n’est garanti. Relisez des fenêtres qui se chevauchent et dédupliquez sur `event_id`.
- **Contrat stable.** Rien n’est renommé ni supprimé, et les nouvelles colonnes arrivent en dernier.
- **Trafic de test.** Demandez à FittingMe une enseigne de test distincte.
- **Conservation.** Les faits restent 13 mois.
- **Effacement.** Un identifiant de corrélation effacé devient le remplacement `FM_`.

## Joindre vos propres analyses

Fournissez un identifiant de corrélation, par exemple un numéro de visite, avec `data-correlation-id` ou [`window.FittingMe.setCorrelationId(id)`](/fr/reference/javascript#identifiant-de-corrélation). N’utilisez jamais d’identifiant personnel, comme une adresse e-mail.

## Exemples de requêtes

Remplacez `FITTINGME_PROJECT.delivered_events_YOUR_KEY` par votre chemin.

Entonnoir quotidien, heure de Paris :

```sql
SELECT
  DATE(occurred_at, 'Europe/Paris') AS day,
  COUNT(DISTINCT IF(event_type = 'session_created', session_key, NULL)) AS sessions,
  COUNT(DISTINCT IF(event_type = 'tryon_photo_ingested', session_key, NULL)) AS with_photo,
  COUNT(DISTINCT IF(event_type = 'tryon_launch', session_key, NULL)) AS with_launch,
  COUNT(DISTINCT IF(event_type = 'tryon_result_revealed', session_key, NULL)) AS with_render,
  COUNT(DISTINCT IF(event_type = 'cart_intent_expressed', session_key, NULL)) AS with_cart_intent
FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1`
WHERE occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
GROUP BY day
ORDER BY day
```

Copie incrémentale sans doublons :

```sql
MERGE `YOUR_PROJECT.YOUR_DATASET.fittingme_events` AS target
USING (
  SELECT *
  FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1`
  WHERE occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 2 DAY)
) AS source
ON target.event_id = source.event_id
WHEN NOT MATCHED THEN
  INSERT ROW
```

Rendus affichés et intentions d’ajout au panier par visite :

```sql
SELECT
  visits.visit_id,
  COUNTIF(events.event_type = 'tryon_result_revealed') AS renders_shown,
  COUNTIF(events.event_type = 'cart_intent_expressed') AS cart_intents
FROM `FITTINGME_PROJECT.delivered_events_YOUR_KEY.events_v1` AS events
JOIN `YOUR_PROJECT.YOUR_DATASET.visits` AS visits
  ON visits.visit_id = events.correlation_id
WHERE NOT STARTS_WITH(events.correlation_id, 'FM_')
  AND events.occurred_at >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)
GROUP BY visits.visit_id
```
