Chargez `https://widget.fittingme.ai/v5/fittingme-loader.js` une seule fois **par intégration**, avec sa configuration sur l’élément script. Chaque script monte une iframe dans un conteneur existant.

<Note>Le contrat à plusieurs vues ci-dessous est un brouillon pour une version compatible du loader, du widget et de l’API. Confirmez sa disponibilité dans votre environnement avant de l’utiliser. Le contrat `/v4/` publié reste disponible pour les intégrations existantes.</Note>

## Attributs obligatoires

| Attribut | Valeur | Exigence |
| --- | --- | --- |
| `data-api-base` | URL de base de l’API, généralement `https://api.fittingme.ai` | Doit correspondre à l’environnement de la clé. |
| `data-retailer-key` | Clé détaillant publiable | Obligatoire ; utilisez la clé autorisée pour le nom d’hôte de la boutique. |
| `data-product-id` | Identifiant produit du commerçant | Obligatoire même si vous fournissez une image de vêtement. |
| `data-journey` | `tryon` | Obligatoire pour l’intégration décrite dans ce guide. |

Une entrée obligatoire manquante ou vide empêche le montage. Aucun parcours n’est sélectionné implicitement.

## Attributs facultatifs

| Attribut | Valeur par défaut si omis | Comportement |
| --- | --- | --- |
| `data-garment-image-urls` | Recherche dans le catalogue | Une URL d’image HTTPS ou un tableau JSON d’URL montrant des vues du même produit et de la même couleur. Les images du catalogue sont prioritaires. |
| `data-garment-image-url` | Recherche dans le catalogue | Ancien alias à une photo, désormais déconseillé. Il reste pris en charge jusqu’à une décision distincte de suppression. |
| `data-container` | `#fittingme-widget-container` | Sélecteur CSS correspondant au conteneur existant. Son contenu est géré par FittingMe. |
| `data-trigger-mode` | Déclencheur géré par la page hôte | `widget` pour le point d’accès FittingMe ; `host` pour un bouton contrôlé par votre page. |
| `data-locale` | Français par défaut | Langue du widget : `en` ou `fr` ; les variantes régionales prises en charge reviennent à leur langue de base. La page de capture sur téléphone utilise la langue de son navigateur. |
| `data-widget-url` | `https://widget.fittingme.ai/tryon/` | Remplacement explicite du document du widget pour un environnement attribué. Assurez la compatibilité du loader, du widget et de l’API. |

`data-sizing-domain` appartient à l’intégration distincte de recommandations de taille et n’est pas nécessaire pour l’essayage virtuel.

## Validation et transmission

- Le loader n’accepte qu’une liste définie d’attributs `data-*`. N’ajoutez pas à ce script de métadonnées analytiques ou propres à votre framework ; placez-les plutôt sur un élément qui vous appartient.
- La valeur plurielle accepte une URL simple ou un tableau JSON de chaînes URL. Une chaîne encodée en JSON, un objet, un scalaire, `null` ou un JSON mal formé est invalide. Une valeur plurielle vide, composée d’espaces ou égale à `[]` utilise le catalogue.
- Chaque URL est nettoyée de ses espaces périphériques avant validation et déduplication dans l’ordre. Les espaces internes, identifiants intégrés, fragments, URL non HTTPS et URL de plus de 1 024 caractères Unicode avant ou après sérialisation restent invalides. Les éléments invalides d’un tableau sont ignorés sans conversion.
- Si les deux attributs d’image sont présents, le loader signale une erreur de configuration et utilise seulement la valeur plurielle, même vide ou invalide. Il ne fusionne ni ne récupère l’ancienne valeur.
- Les images utilisables du catalogue sont prioritaires. Les vues fournies ne servent que de repli et ne complètent jamais un ensemble du catalogue. Une configuration fournie inutilisable permet toujours d’employer des images éligibles du catalogue ; sans image éligible, l’état d’indisponibilité habituel s’applique.
- Les attributs `data-*` inconnus et les parcours non pris en charge sont signalés comme refusés dans la console.
- Une langue inconnue entraîne un repli ; elle ne crée pas de traduction. Pour une boutique anglophone, définissez explicitement `data-locale="en"`.
- `data-container` et `data-widget-url` configurent le loader ; ils ne sont pas transmis au widget comme paramètres d’URL.
- Le loader déduit `host_origin` de la page et choisit la version majeure du protocole de messages. N’ajoutez ni `data-host-origin` ni `data-loader-major`.

Le loader `/v5/` utilise les messages anglais `fittingme/5` et exige que le widget et l’API confirment explicitement la capacité plurielle. Une ancienne version ne peut pas accepter silencieusement une seule vue. Le chemin du fichier et la version du protocole sont deux contrats distincts. Indiquez explicitement `data-trigger-mode="widget"` pour afficher le déclencheur du widget. Une valeur omise, vide ou inconnue conserve le mode hôte. Les alias français sont décrits dans la [migration](/fr/reference/compatibility#compatibilité-française-temporaire).

## Durée de vie

Toutes les entrées sont lues lors de l’exécution du script. Modifier ses attributs par la suite n’a aucun effet. Pour le remplacer, consultez [Changements de produit](/fr/integration/product-changes).

Si le sélecteur ne trouve aucun conteneur, rien n’est monté. Si une autre intégration active utilise déjà l’élément, le doublon est ignoré. Prévoyez un conteneur unique par intégration et placez-le avant le script.

Consultez le [démarrage rapide complet](/fr/start/quickstart) pour le code HTML à copier, les [exigences relatives aux images](/fr/integration/products#exigences-pour-l’url-de-l’image) et les [méthodes JavaScript](/fr/reference/javascript).
