Le loader crée `window.FittingMe`. Attendez le chargement du script avant d’y accéder. Le chargement du script et l’éligibilité de l’intégration sont deux choses distinctes : pour l’ouvrir, le [résultat d’amorçage](/fr/reference/events#résultat-de-l’amorçage) doit être éligible.

## Cibler une intégration

Transmettez l’élément DOM réel du conteneur ou de l’iframe. Dans le code de l’application, il est généralement plus simple de gérer une référence au conteneur.

```javascript
const container = document.getElementById('fittingme-widget-container');
const fm = window.FittingMe;
const state = fm.resolve(container);
```

Ne transmettez pas de chaîne sélecteur aux méthodes de commande. N’utilisez pas les identifiants d’iframe générés comme identifiants dans votre application.

## Méthodes

| Méthode | Valeur renvoyée | Comportement |
| --- | --- | --- |
| `resolve(element)` | Instantané d’état ou `undefined` | Lit une intégration active. Une référence inconnue ou détruite renvoie `undefined` sans erreur. |
| `open(element)` | Chaîne de verdict | Demande l’ouverture. L’amorçage doit être terminé et éligible. Si le panneau est déjà ouvert, la demande est acceptée sans le rouvrir. |
| `close(element)` | Chaîne de verdict | Demande la fermeture et annule toute ouverture en attente. Fermer une intégration déjà fermée est accepté. |
| `destroy(element)` | Chaîne de verdict | Supprime l’intégration fermée et les ressources gérées par le loader. La suppression est refusée si son panneau est ouvert. |
| `on(handler)` | Fonction de désabonnement | S’abonne à toutes les intégrations de la page. Filtrez chaque événement par `embed`. |

Si le panneau est ouvert, appeler `close(element)` puis immédiatement `destroy(element)` est dangereux : la destruction renvoie `drawer_open`. Supprimer tout de même le conteneur peut laisser la page bloquée. `closed` confirme la fermeture, mais ne garantit pas que l’événement `completed` qui suit a été transmis. Consultez les [limites du remplacement](/fr/integration/react#fermer-avant-de-remplacer).

Les commandes renvoient leur résultat de façon synchrone. `accepted` signifie que la commande a été acceptée ; observez les événements pour connaître l’état obtenu. Une demande d’ouverture faite avant la fin de l’amorçage est refusée, et non mise en attente.

## Identifiant de corrélation

`window.FittingMe.setCorrelationId(id)` définit l’identifiant de corrélation de votre page, la valeur de jointure des [Événements Livrés](/fr/reference/delivered-events#joindre-vos-propres-analyses). C’est une méthode de page, pas une commande d’intégration : elle ne prend aucun élément, s’applique à toutes les intégrations de la page et ne renvoie rien.

- Passez 1 à 128 caractères de texte qui ne commencent pas par `FM_`. Passez `""`, `null` ou `undefined` pour effacer la valeur.
- La dernière valeur l’emporte, qu’elle vienne de cette méthode ou de l’attribut [`data-correlation-id`](/fr/reference/configuration#attributs-facultatifs). Définir de nouveau la même valeur ne change rien.
- Une intégration prend la valeur en vigueur à l’ouverture de son panneau. Une valeur définie panneau ouvert s’applique à partir de l’ouverture suivante.
- Une valeur refusée (pas du texte, plus de 128 caractères ou préfixe `FM_`) écrit un avertissement dans la console, ne lève jamais d’exception et ne laisse aucun identifiant de corrélation en vigueur, pas même le précédent.
- La méthode existe dès que la première balise script du loader a été acceptée. Avant cela, utilisez l’attribut.

N’y placez jamais d’identifiant personnel direct, comme une adresse e-mail.

## Instantané d’état

```javascript
// Shape returned by resolve(container); values shown are illustrative.
({
  embed: container,
  journey: 'tryon',
  outcome: 'eligible',
  drawer_open: false
});
```

`outcome` vaut `undefined` tant que l’amorçage n’a pas produit de résultat. Il vaut ensuite `eligible`, `ineligible` ou `indeterminate`. `drawer_open` est un booléen. Chaque appel renvoie un instantané distinct ; le conserver ne donne pas accès à un objet d’état dynamique.

## Verdicts des commandes

| Valeur exacte | Signification | Étape suivante |
| --- | --- | --- |
| `accepted` | Acceptée, éventuellement sans changement si l’état demandé est déjà actif. | Observez l’événement ou relisez l’état. |
| `unknown_embed` | L’élément ne correspond à aucune intégration connue. | Vérifiez l’élément et l’ordre de montage. |
| `embed_destroyed` | L’intégration référencée a été détruite. | Cessez d’utiliser l’ancienne référence ou montez une nouvelle intégration. |
| `bootstrap_incomplete` | L’amorçage est en cours ou indéterminé. | Attendez un nouveau résultat ou diagnostiquez l’échec de l’amorçage. |
| `embed_ineligible` | L’intégration ne peut pas être ouverte. | Vérifiez les données produit et sa disponibilité pour l’enseigne. |
| `fullscreen_unavailable` | Un élément parent empêche l’affichage correct en plein écran. | Corrigez le problème de bloc conteneur signalé dans la console. |
| `drawer_open` | La destruction a été demandée alors que le panneau était ouvert. | Fermez-le, attendez la confirmation de fermeture, puis détruisez l’intégration. |

Comparez exactement les valeurs anglaises indiquées. Les commandes refusées signalent une erreur dans la console et n’effectuent pas l’action demandée.

## S’abonner et nettoyer

```javascript
const unsubscribe = fm.on(event => {
  if (event.embed !== container) return;
  if (event.type === 'bootstrap') {
    const canOpen = event.outcome === 'eligible';
    // Update your button state using canOpen.
  }
});

// When this subscriber's owner is disposed:
unsubscribe();
```

Pour chaque intégration active, le dernier résultat d’amorçage connu est transmis de façon synchrone lors de l’abonnement. Les événements d’ouverture, de fermeture et de complétion ne sont pas rejoués. Initialisez les valeurs utilisées par le gestionnaire avant d’appeler `on()` ; depuis le gestionnaire d’amorçage rejoué, n’appelez pas une variable de désabonnement qui n’a pas encore reçu de valeur.

Vous pouvez vous désabonner plusieurs fois sans risque. La destruction d’une intégration ne désabonne pas votre gestionnaire global. Pour connaître la séquence complète, consultez [Remplacement et nettoyage](/fr/integration/react#fermer-avant-de-remplacer).

## Anciennes formes d’appel

Les méthodes de compatibilité telles que `open()` sans argument, `get()` et les méthodes de handle ne ciblent pas les intégrations de la même manière et ne suivent pas le contrat explicite de verdict décrit ci-dessus. Pour toute nouvelle intégration, utilisez les commandes ciblant un élément, surtout si la page comporte plusieurs intégrations.
