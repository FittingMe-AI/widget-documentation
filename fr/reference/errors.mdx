## Réponses Problem Details

Les erreurs du service utilisent `application/problem+json`. Un proxy, un blocage du navigateur ou un échec de transport peut ne donner ni corps JSON ni `code`.

| Champ | Signification |
| --- | --- |
| `type` | Identifiant stable sous `https://fittingme.ai/problems/`, qui n’est pas un lien. |
| `title` | Catégorie d’erreur. |
| `status` | Statut HTTP. |
| `detail` | Texte destiné aux humains. Ne l’analysez pas. |
| `code` | Dernier segment de `type`. |
| `instance` | Chemin de la requête, sans la chaîne de requête. |
| `field` | Champ de saisie, le cas échéant. |
| `capability` | Fonctionnalité, le cas échéant. |

## Erreurs courantes du parcours

| Code ou statut | Cause | Rétablissement |
| --- | --- | --- |
| HTTP 401 | La clé a été révoquée après le chargement du widget. Une clé manquante, invalide, d’un autre environnement ou révoquée avant le chargement n’atteint jamais l’API : le navigateur bloque l’iframe. | Corrigez la clé. |
| HTTP 403 | L’erreur vient du domaine, du consentement ou du droit d’accès. Lisez le code. | Corrigez la cause. Ne répétez pas la requête. |
| `origin_not_allowed` / HTTP 403 | L’origine de la page ne figure pas parmi les domaines de la clé. | Demandez à FittingMe d’ajouter le nom d’hôte de la boutique à la clé, puis rouvrez. |
| `origin_underivable` / HTTP 403 | Le service ne trouve pas l’origine de la page. | Utilisez une page HTTP(S) et le loader. Ne falsifiez jamais les en-têtes d’origine. |
| `validation_error` | L’entrée indiquée par `field` est invalide. | Corrigez l’entrée. |
| `consent_required` | Aucun consentement à la génération n’a été donné pour cette session. | Repassez par l’étape de consentement. |
| `capability_not_entitled` | L’enseigne n’a aucun accès Try-On. | Demandez à FittingMe de vérifier le compte. |
| `not_found` | La ressource ou le parcours n’existe plus. Avec le `detail` « Product is unavailable », FittingMe ne peut pas proposer l’essayage pour ce produit, par exemple faute de photo du vêtement utilisable. | Commencez un nouveau parcours. Pour « Product is unavailable », vérifiez l’identifiant produit et les hôtes d’images de la clé. |
| `conflict` | Une génération est déjà en cours. | Attendez que cette génération se termine. |
| `payload_too_large` | La photo est trop grande. | Utilisez une photo plus petite. |
| `unsupported_media_type` | Le type de photo n’est pas pris en charge. | Utilisez une photo prise en charge. |
| `image_invalid` / HTTP 422 | Cette image ne peut pas servir à l’essayage. | Utilisez une autre image. |
| `rate_limited` / HTTP 429 | Trop de requêtes ont été envoyées. | Si une réponse contient `Retry-After`, attendez cette durée avant de réessayer. Ne réessayez pas en parallèle. |
| `session_limit_reached` / HTTP 429 | La session a atteint sa limite de photos ou de lancements d’essayage (titre « Limite de la session atteinte »). Pas de `Retry-After` : la limite ne se rouvre pas dans cette session. | Le widget en informe l’acheteur. Ne réessayez pas. |
| `service_unavailable` | Un service requis a échoué. | Réessayez quelques fois. Si les échecs persistent, signalez-les. |
| `maintenance_shutoff` | Le service a désactivé le parcours. | Gardez les achats disponibles. Interrogez votre contact FittingMe. |
| `internal_error` / HTTP 500 | Une défaillance inattendue est survenue. | Faites une nouvelle tentative. Si l’erreur se répète, signalez-la. |

Signalez un code inconnu avec son contexte. Ne le lisez jamais comme un produit éligible ou inéligible.

## Refus de photo et défaillance du service

FittingMe lit chaque nouvelle photo dès que l’acheteur l’ajoute. Un refus à cette étape demande une autre photo et ne propose pas Lancer l’essayage. Le lancement d’une photo refusée renvoie HTTP 422 `image_invalid`. Ce code couvre également d’autres images inutilisables sans en préciser la cause : ne répétez pas le lancement et n’en déduisez aucune cause. Si la lecture est trop lente ou indisponible, le parcours reste disponible.

Le fournisseur peut aussi refuser une photo après Lancer l’essayage. Le widget propose alors de changer de photo ou de revenir au produit. Les codes du fournisseur ne sont pas des diagnostics publics. Un échec de téléchargement ou de décodage du vêtement utilise le rétablissement du service et n’incrimine pas la photo. Consultez le [dépannage](/fr/troubleshooting/symptoms).

## Échecs sans événement d’erreur public

Un refus `frame-ancestors` bloque l’iframe avant l’amorçage, sans corps d’API. Demandez à FittingMe d’ajouter la page aux [domaines de la clé](/fr/start/prerequisites#vérifier-l’encadrement-de-la-boutique). Une clé manquante, inconnue, d’un autre environnement ou révoquée donne aussi ce refus : corrigez la clé. Si l’API FittingMe est injoignable, aucun widget n’apparaît. Si le produit n’a pas d’image du catalogue utilisable, une photo de page invalide échoue après Lancer l’essayage. Vérifiez les [exigences pour l’URL de l’image](/fr/integration/products#exigences-pour-l’url-de-l’image).

## Éviter les boucles de nouvelles tentatives

Le widget gère le parcours et ses requêtes : ne les interrogez pas et ne les rejouez pas. Si l’amorçage reste indéterminé, affichez un état indisponible et gardez votre boutique fonctionnelle.
