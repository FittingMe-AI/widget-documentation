## Réponses Problem Details

Les erreurs du service utilisent `application/problem+json`. Un proxy, un blocage du navigateur ou un échec de transport peut ne donner ni corps JSON ni `code`.

| Champ | Signification |
| --- | --- |
| `type` | Identifiant stable sous `https://fittingme.ai/problems/`, pas un lien. |
| `title` | Catégorie d’erreur. |
| `status` | Statut HTTP. |
| `detail` | Texte destiné aux humains. Ne l’analysez pas. |
| `code` | Dernier segment de `type`. |
| `instance` | Chemin de la requête, sans la chaîne de requête. |
| `field` | Champ de saisie, le cas échéant. |
| `capability` | Fonctionnalité, le cas échéant. |

## Erreurs courantes du parcours

| Code ou statut | Cause | Rétablissement |
| --- | --- | --- |
| HTTP 401 | Clé manquante, invalide, du mauvais environnement ou révoquée. | Corrigez la clé. |
| HTTP 403 | Domaine, consentement ou droit d’accès. Lisez le code. | Corrigez la cause. Ne répétez pas la requête. |
| `origin_not_allowed` / HTTP 403 | L’origine de la page ne figure pas parmi les domaines de la clé. | Ajoutez le nom d’hôte de la boutique à la clé, puis rouvrez. |
| `origin_underivable` / HTTP 403 | Le service ne trouve pas l’origine de la page. | Utilisez une page HTTP(S) et le loader. Ne falsifiez jamais les en-têtes d’origine. |
| `validation_error` | L’entrée indiquée par `field`. | Corrigez l’entrée. |
| `consent_required` | Aucun consentement à la génération pour cette session. | Repassez par l’étape de consentement. |
| `capability_not_entitled` | Aucun accès Try-On pour l’enseigne. | Demandez à FittingMe de vérifier le compte. |
| `not_found` | La ressource ou le parcours n’existe plus. | Commencez un nouveau parcours. |
| `conflict` | Une génération est déjà en cours. | Attendez-la. |
| `payload_too_large` | La photo est trop grande. | Utilisez une photo plus petite. |
| `unsupported_media_type` | Le type de photo n’est pas pris en charge. | Utilisez une photo prise en charge. |
| `image_invalid` / HTTP 422 | Cette image ne peut pas servir à l’essayage. | Utilisez une autre image. |
| `rate_limited` / HTTP 429 | Trop de requêtes. | Si une réponse contient `Retry-After`, attendez cette durée avant de réessayer. Ne réessayez pas en parallèle. |
| `service_unavailable` | Un service requis a échoué. | Réessayez quelques fois. Signalez les échecs persistants. |
| `maintenance_shutoff` | Le service a désactivé le parcours. | Gardez les achats disponibles. Interrogez votre contact FittingMe. |
| `internal_error` / HTTP 500 | Défaillance inattendue. | Faites une nouvelle tentative. Signalez les répétitions. |

Signalez un code inconnu avec son contexte. Ne le lisez jamais comme un produit éligible ou inéligible.

## Refus de photo et défaillance du service

Le fournisseur peut refuser une photo après Lancer l’essayage. Le widget propose alors de changer de photo ou de revenir au produit. Les codes du fournisseur ne sont pas des diagnostics publics. Un échec de téléchargement ou de décodage du vêtement utilise le rétablissement du service et n’incrimine pas la photo. Consultez le [dépannage](/fr/troubleshooting/symptoms).

## Échecs sans événement d’erreur public

Un refus `frame-ancestors` bloque l’iframe avant l’amorçage, sans corps d’API. Obtenez [l’autorisation d’encadrement](/fr/start/prerequisites#faire-approuver-l’encadrement-de-la-boutique). Une image du vêtement invalide échoue après Lancer l’essayage : vérifiez les [exigences pour l’URL de l’image](/fr/integration/products#exigences-pour-l’url-de-l’image).

## Éviter les boucles de nouvelles tentatives

Le widget gère le parcours et ses requêtes : ne les interrogez pas et ne les rejouez pas. Si l’amorçage reste indéterminé, affichez un état indisponible et gardez votre boutique fonctionnelle.
