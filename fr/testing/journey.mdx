Pour chaque essai, consignez la version, le nom d’hôte, le navigateur, l’appareil, le produit, la source de l’image et l’heure. N’incluez ni clés, ni photos, ni liens de capture dans les rapports partagés.

## Effectuer le parcours normal

| Action | Résultat attendu |
| --- | --- |
| Ouvrir une fiche produit | Une intégration se monte. |
| Ouvrir l’essayage | Le panneau s’ouvre ; la page reste immobile. |
| Accepter le consentement | L’étape photo s’ouvre. |
| Ajouter une photo de test | Le parcours l’accepte ou affiche une erreur. |
| Lancer la génération | Un résultat ou un échec récupérable s’affiche. |
| Examiner le résultat | Il montre le vêtement sélectionné. |
| Fermer | Le défilement et le focus reviennent. |
| Rouvrir | Le parcours reprend ou redémarre. |

## Vérifier le transfert de l’ordinateur au téléphone

1. Affichez le QR code sur ordinateur.
2. Scannez-le avec un téléphone, ou ouvrez son URL dans un autre contexte de navigateur.
3. Terminez l’étape photo. L’ordinateur reprend le parcours.
4. Annulez, puis recommencez. L’ancienne et la nouvelle tentative ne se mélangent pas.

Un contexte de navigateur distinct ne teste pas un téléphone physique.

## Provoquer volontairement des échecs

| Cas | Résultat attendu |
| --- | --- |
| Clé révoquée | HTTP 401. Le widget peut rester invisible. |
| Origine sans autorisation d’encadrement | Le navigateur bloque l’iframe. |
| Origine absente des domaines de la clé | L’ouverture échoue avec `origin_not_allowed`. |
| Image du vêtement inutilisable | FittingMe utilise l’image du catalogue si le produit en a une. Sinon, l’essayage échoue après Lancer l’essayage. |
| Produit non activé | Votre déclencheur reste indisponible. |
| Script bloqué | Le panier et le paiement fonctionnent. |
| Annulation pendant la génération | Le panneau propose une étape suivante. |
| Double-clic | Un seul panneau s’ouvre. |
| Changement de couleur | Le nouveau vêtement s’affiche. |
| Refus du fournisseur après Lancer l’essayage | Les actions pour changer de photo et revenir au produit s’affichent. |

Utilisez des clés jetables pour les tests de révocation. Ne créez pas de contenu dangereux pour provoquer un refus.

## Vérifier la mise en page et l’accessibilité

Testez les largeurs de téléphone et d’ordinateur, le clavier, la touche Échap et le zoom à 200 %. Vérifiez que le bouton de retour ferme le panneau pour chaque méthode d’ouverture livrée. Pour les changements de produit, consultez [Boutiques monopages et dynamiques](/fr/integration/react).
