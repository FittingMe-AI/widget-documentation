## Separate the credentials

| Value | Where it belongs |
| --- | --- |
| Publishable key | The browser embed |
| Portal password and codes | The portal login only |
| Service credentials | Never in storefront code |
| Capture links, private image URLs | The journey only, never analytics |

Use separate local and production keys. A local key has `localhost` as its only domain.

## Allow the loader and frame

With a Content Security Policy, add these lines:

```text
script-src https://widget.fittingme.ai
frame-src https://widget.fittingme.ai
```

Add these sources to your existing `script-src` and `frame-src` directives. They are not a full header. You do not need `unsafe-inline`.

## Confirm the three independent access checks

1. Make sure that your CSP allows the loader and frame.
2. Ask FittingMe to [approve your origin for framing](/start/prerequisites#confirm-storefront-framing-approval).
3. Add the storefront hostname to the key's domains.

## Preserve the iframe boundary

Do not wrap the iframe or change its sandbox. The loader checks the source of each message. Never post messages to `*`. Use HTTPS garment image URLs.

## Map the shopper data flow

Loader events do not expose the photo or the result. Generation consent is not analytics consent.

## Before launch

Make sure that analytics exclude private data. Test under your production CSP and consent manager.
