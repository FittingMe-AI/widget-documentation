## Place the embed outside React

Keep the embed in the page template. Add a React mount point beside the widget container:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Example product page</title>
</head>
<body>
  <!-- Render these siblings in the page template, outside React. -->
  <div id="try-on-react-root"></div>
  <div id="fittingme-widget-container"></div>
  <script async src="https://widget.fittingme.ai/v5/fittingme-loader.js"
    data-api-base="https://api.fittingme.ai"
    data-retailer-key="YOUR_PUBLISHABLE_KEY"
    data-product-id="YOUR_PRODUCT_ID"
    data-garment-image-urls="https://images.example.com/YOUR_GARMENT.jpg"
    data-journey="tryon"
    data-locale="en"
    data-trigger-mode="widget"
    data-container="#fittingme-widget-container"></script>
</body>
</html>
```

Mount React into `try-on-react-root`. Never let React render or remove the widget container.

## Observe state from React

The effect owns only its subscription and timers. Do not call `close()` or `destroy()` in its cleanup. The 15-second deadline is your choice.

```jsx
'use client';
import { useEffect, useState } from 'react';

export function TryOnStatus() {
  const [message, setMessage] = useState('Loading try-on…');

  useEffect(() => {
    let unsubscribe = () => {};
    let poll;
    let connected = false;
    let expired = false;
    setMessage('Loading try-on…');
    const deadline = setTimeout(() => {
      expired = true;
      clearTimeout(poll);
      setMessage('Try-on is taking longer than expected. Reload to retry.');
    }, 15000);

    const connect = () => {
      if (expired || connected) return;
      const container = document.getElementById('fittingme-widget-container');
      const fm = window.FittingMe;
      if (!container || !fm?.resolve(container)) {
        poll = setTimeout(connect, 100);
        return;
      }
      connected = true;
      unsubscribe = fm.on(event => {
        if (event.embed !== container || event.type !== 'bootstrap') return;
        clearTimeout(deadline);
        setMessage(event.outcome === 'eligible' ? '' :
          event.outcome === 'ineligible' ? 'Try-on is unavailable for this product.' :
          'Try-on is temporarily unavailable.');
      });
    };
    connect();

    return () => {
      expired = true;
      clearTimeout(poll);
      clearTimeout(deadline);
      unsubscribe();
      // The page owns the embed. Leave its connected DOM and loader intact.
    };
  }, []);

  return <p role="status">{message}</p>;
}
```

## Change products with a full page load

- Another product or colour image: load its page.
- Another size, same image: keep the embed.
- Other page content: keep the embed.

Disable router interception on product links. The loader has no product or size setter. Editing script attributes or passing a variant to `open()` does not change the garment.

## Close before replacing

To replace an embed without a page load, keep its container until step 4 succeeds:

1. Subscribe to the `closed` event of the embed.
2. Call `FittingMe.close(container)` and check the verdict.
3. Wait for `closed` with a time limit. If the limit expires, keep the embed and offer a page reload.
4. Call `destroy(container)`. Remove the container only after it returns `accepted`.

While the drawer is open, calling `close()` then `destroy()` at once returns `drawer_open`. Removing the container then can lock page scrolling. `closed` and `completed` are separate messages. A `destroy` or unsubscribe in the `closed` handler, or right after a promise that handler resolves, can lose `completed`. No close-and-destroy sequence is sure to keep it. See the [completion limits](/reference/events#completion-is-not-conversion).

## Multiple embeds on one page

Give each embed its own container and script. Filter events on the container element:

```javascript
const jacket = document.getElementById('jacket-tryon');
// The loader script is async: wait up to 15 seconds for window.FittingMe.
let unsubscribe = () => {};
(() => {
  let poll;
  const deadline = setTimeout(() => clearTimeout(poll), 15000);
  const connect = () => {
    const fm = window.FittingMe;
    if (!fm) {
      poll = setTimeout(connect, 100);
      return;
    }
    clearTimeout(deadline);
    unsubscribe = fm.on(event => {
      if (event.embed !== jacket) return;
      // Handle this embed's milestone using your own product context.
    });
  };
  connect();
})();
```

Only one drawer opens at a time. The loader ignores a second script in the same live container.

## Verify

- Mount, unmount and remount the status component before the loader arrives.
- Check that Strict Mode and the production build show one widget.
- Open the drawer, unmount the component and close the drawer. Page scrolling returns.
- Follow a product link. A full page load shows the correct product.
- Block the loader. The status stops waiting after its deadline.
