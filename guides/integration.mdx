## Loader URL

Use the production loader at:

```text
https://cdn.fittingme.ai/fittingme-widget/loader/fittingme-loader.min.js
```

The loader is standalone and has no runtime imports. Each loader tag mounts one iframe and pins it to one Shopper Journey.

## Common attributes

| Attribute | Default | Purpose |
| --- | --- | --- |
| `data-container` | `#fittingme-widget-container` | CSS selector for the host element that receives the iframe. |
| `data-product-id` | Empty | Retailer product identifier forwarded to the widget. |
| `data-api-key` | Empty | Public retailer API key forwarded to the widget. |
| `data-api-url` | `https://api.fittingme.ai` | Backend origin used by the widget. |
| `data-journey` | `tryon` | Journey delivered by this embed: `sizing` or `tryon`. |
| `data-locale` | `en` | Requested widget locale. |
| `data-gender` | Empty | Optional sizing input. |
| `data-brand-slug` | Empty | Optional brand selection. |
| `data-garment-type` | Empty | Optional garment selection. |
| `data-garment-image-url` | Empty | Garment image forwarded for Try-On. Root-relative values resolve against the retailer page. |
| `data-garment-model-key` | Empty | Optional stable grouping for garment variants. |
| `data-privacy-url` | Empty | Retailer privacy-policy URL shown by the widget where applicable. |

Always set `data-api-key`, `data-product-id`, and `data-journey` explicitly for a production embed. Use `data-garment-image-url` when the retailer page supplies the garment image for Try-On.

## API authentication

The loader forwards `data-api-key` to the widget. The widget attaches the value as `X-API-Key` on authenticated backend requests.

```http
X-API-Key: YOUR_PUBLISHABLE_KEY
```

Do not prefix the value with `Bearer`. There is no public `/v1/widget-keys` management API.

## Programmatic controls

After the loader script has executed, `window.FittingMe` exposes the live Journey Embed registry. Resolve an embed by journey and control only that instance:

```javascript
const tryOn = window.FittingMe.get('tryon');

tryOn?.open();
tryOn?.close();
```

Calling `open()` before the iframe signals readiness is safe: the loader buffers that request and replays it after the ready handshake.

Each handle also exposes `destroy()`, which removes only its own iframe and unregisters that instance.

## Container rules

The container must exist when the loader executes. If two loader tags resolve to the same element, the second embed is ignored and the first remains intact.
