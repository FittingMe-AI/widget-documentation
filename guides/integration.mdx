## Loader URL

Use the production loader at:

```text
https://cdn.fittingme.ai/fittingme-widget/loader/fittingme-loader.min.js
```

The loader is standalone and has no runtime imports. Each loader tag mounts one iframe and pins it to one Shopper Journey.

## Common attributes

The loader reads a **closed** attribute list. An attribute outside the list is not
ignored: the loader refuses the embed and names the unknown key in the browser console.

| Attribute | Required | Default | Purpose |
| --- | --- | --- | --- |
| `data-container` | No | `#fittingme-widget-container` | CSS selector for the host element that receives the iframe. |
| `data-api-base` | **Yes** | None | Backend origin the widget calls. |
| `data-retailer-key` | **Yes** | None | Public retailer key forwarded to the widget. |
| `data-product-id` | **Yes** | None | Retailer product identifier forwarded to the widget. |
| `data-journey` | **Yes** | None | Journey delivered by this embed: `sizing` or `tryon`. |
| `data-locale` | No | None — omitted when absent | Requested widget locale. |
| `data-sizing-domain` | No | None — omitted when absent | Sizing domain the embed applies to. |
| `data-trigger-mode` | No | None — omitted when absent | Trigger presentation mode. |
| `data-widget-url` | No | `https://widget.fittingme.ai/<journey>/` | Overrides the artifact address. Retailers do not set it. |

Every declared value is trimmed. A value that trims to empty counts as absent.

<Warning>
  **`data-api-url` and `data-api-key` are the previous names.** A tag that carries them
  *without* `data-api-base` and `data-retailer-key` is still accepted through a
  compatibility path that also forwards `data-gender`, `data-brand-slug`,
  `data-garment-type`, and `data-garment-image-url`. That path is scheduled for removal.
  New integrations must use `data-api-base` and `data-retailer-key`.

  Mixing the two vocabularies on one tag is refused: a tag that speaks the current
  names is held to the closed list above, and the previous names then count as
  unknown keys.
</Warning>

<Note>
  `data-garment-model-key` and `data-privacy-url` were listed here previously. The loader
  has never read them. On a current-vocabulary tag they are refused as unknown keys.
  Remove them from existing markup.
</Note>

## Artifact origin and framing

Each Journey Embed mounts an iframe served from the widget artifact host, one document
per journey:

```text
https://widget.fittingme.ai/sizing/
https://widget.fittingme.ai/tryon/
```

The loader derives that address from `data-journey`. You do not configure it.

<Warning>
  Two browser-level requirements follow, and an embed that meets neither loads your page
  normally while showing nothing.

  1. **Your own Content-Security-Policy must permit the frame.** If your page sends a CSP
     with a `frame-src` (or `default-src`) directive, it must allow
     `https://widget.fittingme.ai`.
  2. **Your origin must be on the widget's framing allowlist.** The artifact host answers
     with a `frame-ancestors` directive naming the origins allowed to frame it. An origin
     that is not on that list is refused by the browser, which reports a Content Security
     Policy violation in the console.

  Send every origin that will embed the widget — production, staging, and preview hosts —
  when you [request a key](/guides/widget-keys). They are added to the framing allowlist.
</Warning>

## API authentication

The loader forwards `data-retailer-key` to the widget. The widget attaches the value as `X-API-Key` on authenticated backend requests.

```http
X-API-Key: YOUR_PUBLISHABLE_KEY
```

Do not prefix the value with `Bearer`. There is no public `/v1/widget-keys` management API.

## Programmatic controls

After the loader script has executed, `window.FittingMe` exposes the live Journey Embed registry. Resolve an embed by journey and control only that instance:

```javascript
const tryOn = window.FittingMe.get('tryon');

tryOn?.open();
tryOn?.close();
```

Calling `open()` before the iframe signals readiness is safe: the loader buffers that request and replays it after the ready handshake.

Each handle also exposes `destroy()`, which removes only its own iframe and unregisters that instance.

## Container rules

The container must exist when the loader executes. If two loader tags resolve to the same element, the second embed is ignored and the first remains intact.
