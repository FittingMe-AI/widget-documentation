## Loader URL

Use the production loader at:

```text
https://widget.fittingme.ai/v2/fittingme-loader.js
```

The loader is standalone and has no runtime imports. Each loader tag mounts one iframe and pins it to one Shopper Journey.

## Common attributes

| Attribute | Default | Purpose |
| --- | --- | --- |
| `data-container` | `#fittingme-widget-container` | CSS selector for the host element that receives the iframe. |
| `data-api-base` | Required | Backend origin, for example `https://api.fittingme.ai`. |
| `data-retailer-key` | Required | Public retailer key assigned to your integration. |
| `data-product-id` | Required | Retailer catalogue product identifier. |
| `data-journey` | Required | Exactly `sizing` or `tryon`; no fallback. |
| `data-locale` | Omitted | Optional requested locale. |
| `data-sizing-domain` | Omitted | Optional sizing domain supplied by your integration configuration. |
| `data-trigger-mode` | Omitted | Optional trigger presentation mode supplied by your integration configuration. |
| `data-widget-url` | `https://widget.fittingme.ai/{journey}/` | Override the widget document only when your integration requires it. The default selects the declared journey. |

Set all four required attributes explicitly. Missing required values, unknown journeys, or unrecognized `data-*` attributes prevent mounting and produce a console error. Attribute values are trimmed at the loader boundary.

The API resolves garment imagery and other product context from `data-product-id`. Do not pass legacy garment-image, brand, gender, or privacy attributes on the loader tag.

## API authentication

The loader forwards `data-retailer-key` to the widget. The widget attaches the value as `X-API-Key` on authenticated backend requests.

```http
X-API-Key: YOUR_PUBLISHABLE_KEY
```

Do not prefix the value with `Bearer`. There is no public `/v1/widget-keys` management API.

## Programmatic controls

After the loader script has executed, `window.FittingMe` exposes the live Journey Embed registry. Resolve an embed by journey and control only that instance:

```javascript
const tryOn = window.FittingMe.get('tryon');

tryOn?.open();
tryOn?.close();
```

Calling `open()` before the iframe signals readiness is safe: the loader buffers that request and replays it after the ready handshake.

Each handle also exposes `destroy()`, which removes only its own iframe and unregisters that instance.

## Container rules

The container must exist when the loader executes. If two loader tags resolve to the same element, the second embed is ignored and the first remains intact.

To let the drawer fill the viewport, keep the element selected by `data-container` and every ancestor up to `<html>` free of CSS that creates a containing block for `position: fixed` descendants. This includes `transform`, `filter`, `perspective`, `backdrop-filter`, `contain` values of `paint`, `layout`, `strict`, or `content`, and `will-change` for any of those properties. Otherwise, the drawer remains constrained to that element's box instead of filling the viewport.

Check carousels, scroll-reveal animations, hover zoom effects, sticky banners, and rendering-isolation wrappers for these properties. Move the container outside the affected subtree or remove the property from the ancestor.
