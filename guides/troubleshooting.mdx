---
title: "Troubleshooting"
description: "Diagnose loader, container, authentication, and API error problems in a FittingMe embed."
---

<Accordion title="The loader does not load">
  Confirm that the script uses the complete production URL:

  ```text
  https://cdn.fittingme.ai/fittingme-widget/loader/fittingme-loader.min.js
  ```

  Inspect the browser Network panel for the loader request. Shorter legacy asset paths are not the deployed loader.
</Accordion>

<Accordion title="No Journey Trigger appears">
  Confirm that the element selected by `data-container` exists before the loader executes. When the selector matches no element, the loader does not create an iframe.

  Set `data-journey` to exactly `sizing` or `tryon`. Missing or invalid values fall back to `tryon` and produce a console warning.

  For Try-On, confirm that the product has usable garment imagery. If the retailer page supplies that image, pass it with `data-garment-image-url`. An ineligible Journey Embed may collapse instead of showing a dead trigger.
</Accordion>

<Accordion title="The API returns 401 Unauthorized">
  Confirm that `data-api-key` contains the public retailer key assigned to the integration. The widget sends this value in `X-API-Key`.

  Do not use `Authorization: Bearer …`. The mounted retailer-authenticated backend routes do not use the Bearer scheme.
</Accordion>

<Accordion title="The second embed is ignored">
  Give every Journey Embed a distinct container element. Duplicate detection uses the resolved element, not the selector text, so two different selectors that point to the same element still count as a duplicate.
</Accordion>

<Accordion title="An API request returns a structured error">
  Inspect the HTTP status and the root `code` member. See [Problem details](/api-reference/errors) for the RFC 9457 response shape and all stable problem types.
</Accordion>

If the integration still fails after these checks, use the [FittingMe contact page](https://fittingme.ai/contact/) and include the affected product identifier, journey, browser, and HTTP status. Never send a live API key.
