---
title: "Multiple embeds"
description: "Target the right placement and coordinate more than one Try-On embed."
---

Every loader script creates at most one embed in its resolved container. Use a different container for each placement. A second script targeting an already occupied container is ignored; changing the CSS selector string does not create a second embed if it resolves to the same element.

## Declare each placement

This example places Try-On for two explicitly selected product contexts. Replace the placeholders and incorporate the boot/error handling from a [complete quickstart](/quickstarts/provided-button).

```html
<div id="primary-tryon"></div>
<div id="secondary-tryon"></div>
<script src="https://widget.fittingme.ai/v2/fittingme-loader.js"
  data-api-base="https://api.fittingme.ai"
  data-retailer-key="YOUR_PUBLISHABLE_KEY"
  data-product-id="YOUR_PRIMARY_PRODUCT_ID"
  data-garment-image-url="https://images.example.com/primary.jpg"
  data-journey="tryon" data-locale="en" data-trigger-mode="encart"
  data-container="#primary-tryon"></script>
<script src="https://widget.fittingme.ai/v2/fittingme-loader.js"
  data-api-base="https://api.fittingme.ai"
  data-retailer-key="YOUR_PUBLISHABLE_KEY"
  data-product-id="YOUR_SECONDARY_PRODUCT_ID"
  data-garment-image-url="https://images.example.com/secondary.jpg"
  data-journey="tryon" data-locale="en" data-trigger-mode="encart"
  data-container="#secondary-tryon"></script>
```

Both script tags use the same loader version. Do not assign a replacement object to `window.FittingMe`, and do not use implicit “last embed” commands.

## Address and subscribe explicitly

```javascript
const primary = document.getElementById("primary-tryon");
const secondary = document.getElementById("secondary-tryon");
const context = new Map([
  [primary, { productId: "YOUR_PRIMARY_PRODUCT_ID", placement: "primary" }],
  [secondary, { productId: "YOUR_SECONDARY_PRODUCT_ID", placement: "secondary" }]
]);
const unsubscribe = FittingMe.on(event => {
  const product = context.get(event.encart);
  if (!product) return;
  // Use this placement's state/UI, never a global selected product here.
  if (event.jalon === "amorçage") {
    event.encart.dataset.bootOutcome = event.issue;
  }
});
// Requests target a DOM element, never the product identifier.
// Only offer this action once the corresponding boot outcome is eligible:
function openSecondary() {
  return FittingMe.open(secondary);
}
```

An `accepté` return is command acceptance. Observe the secondary embed's `ouverture` to know that it opened. Map any custom buttons to their own containers, reveal them only for eligible outcomes and restore focus to the correct button on `fermeture`.

## Let the loader coordinate drawers

The loader permits one drawer at a time. For a commanded open, it closes the busy sibling before opening the target, waiting for the sibling's closure with a bounded fallback. A pending commanded opening also counts as busy. Subscribe before acting to observe the ordered transitions; do not broadcast an open to every iframe or implement a second competing coordinator around the loader.

A silent sibling produces a console diagnostic; a bound is not proof that a close event was observed. Treat missing milestones as an integration failure. The browser must never remain scroll-locked after all drawers are closed.

## Remove one embed safely

1. Close the embed you are removing and wait for its closure if open.
2. Destroy that reference, remove its script, and remove its context from your map.
3. Release the appropriate subscription. If the single global subscriber still serves the other embed, keep it; unsubscribe when its owner finishes. With one subscriber per component, remove only that component's subscription.

Never remove every iframe or delete the shared global to clean up one product. Replacing an embed in an existing container reuses that placement, so dispose the old listener before associating new product context with it.

## Verify isolation

1. Open the first embed, then request the second from a retailer-owned button. Expect the first to close before the second is observed open.
2. Close the second and check focus.
3. Destroy the first and verify the second still works.
4. Remount the first, then count events. Each opening should produce exactly one retailer analytics record for the correct product and placement.

## Direct multi-iframe integrations

For a direct multi-iframe integration, you own the equivalent coordinator and per-frame validation. The [direct quickstart](/quickstarts/direct-protocol) deliberately demonstrates one embed; use the loader for the multi-embed approach shown here.
