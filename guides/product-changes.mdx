title: "Product and image changes"
description: "Keep the Try-On context aligned with selected colors, images and SPA routes."
---

An embed pins its product identity, supplied garment image, key, API, locale and trigger mode when created. It does not watch your gallery or product selector. Updating a script attribute after it has executed leaves the existing embed unchanged.

## Decide when to replace

| Storefront change | Action |
| --- | --- |
| Price, stock text or other copy changes for the same garment/image | Keep the embed |
| Selected garment color changes | Replace with the correct product/color identity and image |
| The supplied garment image URL changes | Replace, even if the product identifier stays the same |
| Navigate to another product in an SPA | Close and destroy the old embed before committing the new context |
| An ordinary page navigation | Let the browser end the old document; mount the new page normally |

Do not swap the image inside an existing session, invent an `update()` call or reload the iframe to simulate closing. Supplying an image is optional only when creating the embed; it is not an image-update channel.

## Replace in a controlled sequence

1. Disable the selector and the Try-On trigger while a change is pending.
2. Wait for any opening request to settle. If open, request close and wait for the observed `fermeture` for this container.
3. Keep subscriptions through the completion event that can follow that closure. Confirm the old drawer is closed, then call `destroy(container)`.
4. Unsubscribe your old handlers and remove the old script. Keep the old UI owned if a bounded wait fails; show an error instead of silently forcing deletion.
5. Mount one new configured script against an empty, connected container. Subscribe once with the **new** immutable product context. Wait for eligibility before revealing the new trigger.

The [custom-button quickstart](/quickstarts/custom-button) provides `tryOnExample.dispose()` as retailer-owned sample code for steps 2–4. It is not a method on `FittingMe`.

## A closed-embed mount helper

This helper mounts a replacement only after you have completed teardown. Call it from your product-page controller. It rejects duplicate ownership and preserves a late-loading script for explicit cleanup instead of assuming removal cancels a pending download.

```javascript
function mountProduct(container, { key, productId, imageUrl, onEvent }) {
  if (!container.isConnected || !container.id) throw new Error("A connected, named container is required");
  if (window.FittingMe?.resolve(container)) throw new Error("Destroy the previous embed first");
  const script = document.createElement("script");
  script.src = "https://widget.fittingme.ai/v2/fittingme-loader.js";
  const config = {
    "data-api-base": "https://api.fittingme.ai",
    "data-retailer-key": key,
    "data-product-id": productId,
    "data-journey": "tryon",
    "data-locale": "en",
    "data-trigger-mode": "encart",
    "data-container": "#" + CSS.escape(container.id)
  };
  if (imageUrl !== undefined) config["data-garment-image-url"] = imageUrl;
  for (const [name, value] of Object.entries(config)) script.setAttribute(name, value);
  return new Promise((resolve, reject) => {
    script.onerror = () => { script.remove(); reject(new Error("Loader download failed")); };
    script.onload = () => {
      const api = window.FittingMe;
      if (!api?.resolve(container)) { script.remove(); reject(new Error("Embed did not mount")); return; }
      const unsubscribe = api.on(event => { if (event.encart === container) onEvent(event); });
      resolve({ script, unsubscribe, container });
    };
    document.body.append(script);
  });
}
```

Resolve of this helper means the loader mounted an embed, not that its boot outcome is eligible. Keep the returned script and unsubscribe function for that embed's next teardown. If you need a custom trigger, set `data-trigger-mode="hôte"` and the button/focus handling from the quickstart.

### Handle rapid selections

1. Serialize replacement and retain a generation number.
2. After an asynchronous close or load, compare that number before activating UI.
3. Dispose an obsolete mounted generation before starting the newest one. Do not let an old boot callback reveal a button for the newly selected product.

## Coordinate SPA navigation

1. Await teardown **before** your router commits a new route or removes the placement. Browser history belongs to both the retailer and the embed while the drawer is open; pushing a route first can leave a stale drawer entry.
2. Keep a navigation pending state and preserve the current route if closure times out. Use your framework's navigation integration to run this lifecycle; a generic `popstate` listener is not a substitute for your router's own lifecycle.
3. After navigation, create the container before executing a new loader script. A cached global `FittingMe` does not mount a new embed by itself: one script execution creates one embed.

The [React/Next.js guide](/guides/react-nextjs) keeps iframe ownership independent of React's synchronous removal.

## Verify a product change

1. Open the first garment, close it and select a second color.
2. Inspect the new iframe query parameters locally. The new `product_id` and `garment_image_url` must match the visible product. Do not capture the key or full signed URLs in screenshots or logs.
3. Generate a Try-On for that second context and verify its garment.
4. Repeat a rapid A → B → A selection and navigate away/back. Expect one living embed and one analytics subscription per intended placement.
